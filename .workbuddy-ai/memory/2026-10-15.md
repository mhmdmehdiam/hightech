# 2026-10-15 — Deploy setup for High Tech

## Goal
User wants a public link to show the store to a friend who is not nearby.
Chose **Vercel over Netlify** (user confirmed: has GitHub account, repo not pushed yet).

## Why Vercel, not Netlify
The app has a **file-backed backend**: `lib/db.ts` writes `data/*.json` via `fs.writeFile`,
and uploads go to `public/uploads/`. Netlify has no persistent writable filesystem, so the
admin panel would be dead. Vercel runs it as-is and (being the Next.js vendor) needs zero config.

## What works / doesn't on Vercel
- ✅ all pages, cart, search/filter (cart is localStorage, JSON is read-only)
- ⚠️ admin login succeeds but writes don't persist
- ❌ product edits / order saves don't persist

Acceptable for a demo link. Documented in `DEPLOY.md`.

## Code change made for deploy safety
`lib/db.ts` → `getSessionSecret()` used to throw when the FS is read-only (it tried to write
`session.secret`). Now:
1. `process.env.SESSION_SECRET` wins if set
2. else try the file
3. else attempt write; on failure fall back to a `sha256` of
   `hightech-fallback|process.env.VERCEL_URL` so sessions stay valid per instance.

## Repo state
- `.gitignore` extended to exclude: `/.playwright-cli/`, `/capture/`,
  `/scripts/zajno-*.mjs`, `/data/session.secret`, `/public/uploads/`, OS/editor noise.
- Two commits on `main`: `0cce5db` (full build, 105 files) and `b923680` (deploy guide).
- **No remote configured yet** — user must run `git remote add origin <url>` + `git push -u origin main`.
- ⚠️ `data/users.json` IS committed — it holds the admin password hash. Repo must be **private**.
- Added `vercel.json` (framework nextjs, npm build/install).

## Docs created
- `high-tech-next/DEPLOY.md` — step-by-step: GitHub repo → push → Vercel import →
  `SESSION_SECRET` env var → share link. Includes a troubleshooting table and the
  `npx vercel` no-GitHub alternative.

## Gotcha for future turns
`npm run build` triggers a sandbox delete-confirmation for `.next/types/validator.ts`
because of `cacheComponents`. The user cancelled it once. Build had already succeeded
earlier, so prefer `npx tsc --noEmit` for a quick correctness check when a full build
isn't strictly needed.

# 2026-10-15 (بخش سوم) — بهبود گرافیک سایت

## ⚠️ تله‌ی محیطی مهم (این را حتماً یادت باشد)
**همیشه سایت را با `http://localhost:3000` باز کن، نه `http://127.0.0.1:3000`.**
Next.js 16 دسترسی cross-origin به منابع dev را بلاک می‌کند:

```
⚠ Blocked cross-origin request to Next.js dev resource /_next/hmr from "127.0.0.1".
```

نتیجه: از `127.0.0.1` **هیچ `useEffect` ای در کل اپ اجرا نمی‌شود** —
ولی کلیک‌ها کار می‌کنند (هیدریشن انجام شده، فقط flush افکت‌ها می‌میرد).
من چند ساعت را صرف شکار یک باگ انیمیشن وهمی کردم که فقط از این تله می‌آمد.
اثبات: از `localhost` کلید `hightech_cart_v2` در localStorage نوشته می‌شود،
از `127.0.0.1` نمی‌شود. راه‌حل جایگزین: `allowedDevOrigins` در next.config،
ولی بهتر است فقط از localhost استفاده شود.

## علت واقعی (با ابزار اثبات شد)
`components/RevealObserver.tsx` یک `IntersectionObserver` را **همزمان داخل
`useEffect`** می‌ساخت و `classList.add('in')` می‌زد روی همه‌ی
`.reveal/.clip-img`های داخل viewport. آن گره‌ها **مالکیتشان با React است**.
پس ریس بین observer و walk هیدریشن React پیش می‌آمد:

```
- Server: <article className="card reveal clip-img">
+ Client: <article className="card reveal clip-img in">   ← classList.add
```

هرچه کارت بیشتر روی صفحه → walk هیدریشن طولانی‌تر → observer مطمئن‌تر
برنده می‌شود. **دقیقاً به همین دلیل فقط روی `/shop` (۱۶ کارت) رخ می‌داد و

فایل‌های جدید:

## بخش دهم — رفع خطای «Blocking Route» و کشف ریشه‌ی واقعی خطاهای hydration

### خطای جدید
اسکرین‌شات سوم کاربر یک خطای تازه بود (دو تای اول همان hydration تشخیص‌داده‌شده):
```
Error: Route "/admin/settings": Next.js encountered the unstable value
`Date.now()` while prerendering.
lib/auth.ts (30:44) @ verify
```

### علت
`cacheComponents: true` در `next.config.ts` باعث می‌شود Next روت‌ها را
prerender کند. لایوت پنل ادمین کوکی سشن را می‌خواند و `verify()` در
`lib/auth.ts:30` انقضا را با `Date.now()` می‌سنجد → Next مقدار ناپایدار را
حین prerender رد می‌کند. فقط `/admin/*` اثر می‌گیرد: تنها جایی که
`getSession()` در زمان رندر صدا زده می‌شود (APIها prerender نمی‌شوند).

### رفع
- `app/admin/(panel)/layout.tsx`: `await connection()` قبل از `getSession()`
  → کل سگمنت `/admin` در زمان درخواست رندر می‌شود (راه‌حل `[dynamic]` خود Next).
- `lib/auth.ts`: `unstable_noStore()` داخل `getSession()` تا هیچ فراخوانی‌کننده‌ای
  نتواند رندرِ سشن‌خوان را کش/prerender کند.

### اثبات
`next build` حالا در جدول روت‌ها اینها را `ƒ` (Dynamic) نشان می‌دهد:
`/admin`, `/admin/products`, `/admin/posts`, `/admin/settings`, `/admin/orders`.
`/admin/login` درست است که `○` (static) بماند — سشن نمی‌خواند.

### کشف مهم: ریشه‌ی خطاهای hydration سورس نبود
خطاهای hydration برگشتند و **تقصیر کد نبود**. علت: بعد از `npm run build`،
آرتیفکت‌های پروداکشن در `.next` می‌مانند و `next dev` بعدی آنها را قاطی می‌کند
→ کلاینت چانک‌های build را می‌گیرد ولی سرور با dev رندر می‌کند → عدم تطابق
(`+ __html: ""` در کلاینت مقابل `- __html: "<path...>"` در سرور).

**قاعده: اگر build زده‌ای، قبل از `next dev` حتماً `.next` را پاک کن.**

شاهد: قبل از پاک‌سازی ۴ خطای hydration در لاگ؛ بعد از `rm -rf .next` و ری‌استارت
**صفر** — با اجرای دقیقاً همان اسکریپت‌ها روی همان سورس.

### نکات ابزار
- timestampهای `next-development.log` **نسبی**اند (از لحظه‌ی بوت سرور)، نه ساعت
  دیوار. `00:01:10` یعنی ۷۰ ثانیه بعد از استارت — نه ساعت ۰۰:۰۱.
- در Git Bash آرگومان `/` به مسیر ویندوز تبدیل می‌شود؛
  `check-hydration.mjs /` می‌شکند. بدون آرگومان اجرا کن (روت اول پیش‌فرض `/` است).
- ورود ادمین پیش‌فرض: `admin` / `hightech1404` (`DEFAULT_ADMIN` در `lib/db.ts`).
- `check-hydration.mjs` روت `/` را با `checked=0` «PASS» می‌کند؛ یعنی آن روت را
  واقعاً نمی‌سنجد. به تیک سبز آن برای `/` تکیه نکن.

### پاک‌سازی داده
fuzz یک پست زباله ساخت (slug ۶۰ تا `x`، عنوان ۲۰۰۰۰ کاراکتر — از بدنه‌ی
`huge-str`). `scripts/fuzz-api.mjs` حالا خودش ردیف‌های ساخته‌شده را با
`DELETE /api/<res>?id=` پاک می‌کند و اگر چیزی جا بماند FAIL می‌دهد.
بکاپ قبل از پاک‌سازی: `data/backups/hightech-prefix-20261015-115159.db`.
دیتابیس نهایی: ۱۶ محصول / ۵ پست / ۶ دسته / ۱ کاربر / ۰ سفارش — بدون تغییر.

## بخش یازدهم — ریشهی واقعی خطاهای hydration: سرویسورکر در حالت dev

### نشانها
کاربر گفت خطا «هنوز برقراره» و چینش «فهرست کامل» (سکشن کاتالوگ خانه) بهم ریخته.

### علت واقعی
`public/sw.js` برای `/_next/static/` استراتژی **cache-first** داشت. در dev،
Turbopack چانکها را از همان مسیر با URLهای **پایدار و بدون هش محتوایی** سرو
میکند → سرویسورکر همان باندل اولی را برای همیشه به مرورگر میداد:
- تغییر سورس اثر نمیکرد
- کلاینت با کد قدیمی hydrate میشد → خطای hydration (حتی وقتی سورس درست بود)
- رفرش ساده هم کمکی نمیکرد، چون worker قبل از شبکه از کش جواب میداد
- همین برای «توی خوردن» چیدمان کاتالوگ هم کافی است (CSS/JS قدیمی)

### جهت diff این خطا مهم است
```
+ __html: ""        ← Client (قدیمی)
- __html: "<path…"  ← Server (درست)
```
برعکس جلسهی قبل. **تست قاطع:** `curl` بگیر و ببین SSR مسیر آیکون را دارد یا نه.
(این بار داشت: `mouse-path: 1`، `monitor-path: 1` — پس سرور سالم بود.)

### رفع (کامیت `1ffe7b8`)
- `PwaRegister.tsx`: ثبت SW فقط در `NODE_ENV === 'production'`. در dev،
  **فعلاً** unregister میکند و کشها را خالی میکند → مرورگرهای گیرکرده خودشان
  با یک بار لود ترمیم میشوند.
- `sw.js`: نسخهی کش به `ht-v2` ارتقا یافت تا هندلر activate کشهای `ht-v1-*` را
  پاک کند.

### تأیید
- اسکریپت: SW دستی کاشته شد → یک reload → workers:0، caches:[]،
  ۶ آیکون dropdown پر، صفر خطای hydration.
- چیدمان کاتالوگ (`WorkIndex`) در ۱۴۴۰px درست: گرید ۴ ستونه
  `593/128/110/282`، ۱۶ ردیف، ارتفاع ردیف ۵۷px.
- `sweep.mjs`: **۹۸/۹۸** سبز → چیدمان در هیچ ویوپورتی نمیجوزد.
- `tsc` تمیز. کامیت `1ffe7b8`.

### درس
وقتی «خطا با رفرش از بین نمیرود» یا «تغییر سورس اثر نمیکند»، اول سرویسورکر و
کش را چک کن — نه سورس را. Playwright با context تازه SW ندارد، پس همیشه سبز
میشد و مشکل را پنهان میکرد.
